# Inductor: convolution on an input with unbacked height/width fails with `GuardOnDataDependentSymNode`

### System info

- torch: `2.16.0a0+git57f02f8` (source build, CUDA 12.8)
- transformers: `5.24.0.dev0` (main, git `046bdb8cc2`)
- Python 3.15, Linux. CPU and CUDA (B300)

### Description

With `capture_scalar_outputs` and `capture_dynamic_output_shape_ops` on (`dynamic=True`), Apertus 1.5's vision
tokenizer fails while Inductor lowers its first convolution:

```
InductorError: LoweringException: GuardOnDataDependentSymNode: Could not extract specialized integer from
data-dependent expression 256*Max(1, u4)*Max(1, u5)
  target: aten.convolution.default
  args[0]: ReinterpretView(..., size=[1, 3, u4, u5], stride=[3*s58**2, s58**2, s58, 1])
```

The model crops each image to its own size, which it reads from a tensor (`u4`, `u5` are unbacked), and runs
`conv_in` on the crop (`modeling_apertus1p5.py`, `Apertus1p5VisionTokenizerEncoder.forward`). The convolution
lowering needs a concrete value for an expression in the unbacked sizes and throws instead of using a fallback
hint. The same model passes with the default (backed) `dynamic=True`, where the crop size is specialized.

**Not reduced yet.** Likely shape of a repro: `x[:, :h, :w]` with `h, w = sizes.tolist()`, then `nn.Conv2d`,
compiled with `torch._dynamo.config.capture_scalar_outputs = True`. Model-level command:

```
python -m graph_breaks.dynamic --unbacked --model apertus1p5_vlm --scenario eval_forward [--device cuda]
```

### Possible fix

Use `size_hint(..., fallback=...)` / `optimization_hint` for the size-dependent heuristics in the convolution
lowering (layout choice, workspace size) instead of guarding.
