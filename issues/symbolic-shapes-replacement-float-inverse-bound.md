# `torch._check(u0 == 32 * s0)` fails with `tgt_bound not a subset of src_bound`: float rounding when inverting the replacement bound

### System info

- torch: `2.16.0a0+git57f02f8` and `2.16.0a0+gitf29b6d5` (main, Nov 24 2026), CPU and CUDA
- transformers: `5.24.0.dev0` (main, git `046bdb8cc2`)
- Python 3.15, Linux

### Description

With `capture_dynamic_output_shape_ops` on, an equality check between an unbacked size and a multiple of a
backed size fails while Dynamo runs the `torch._check` on fake tensors:

```
TorchRuntimeError: Dynamo failed to run FX node with fake tensors: call_function <function _check>(*(Eq(u0, 32*s23),), **{}):
got AssertionError('tgt_bound=VR[64, 9223372036854775808] not a subset of src_bound=VR[64, 9223372036854775806]')
```

Repro (CPU, 15 lines): [`issues/repros/check_eq_unbacked_backed_product_bound.py`](repros/check_eq_unbacked_backed_product_bound.py)

```python
torch._dynamo.config.capture_scalar_outputs = True
torch._dynamo.config.capture_dynamic_output_shape_ops = True

def f(embeds, ids):
    mask = (ids == 7).unsqueeze(-1).expand_as(embeds)
    n = embeds[mask].numel()                  # unbacked u0, range [0, sys.maxsize - 1]
    torch._check(n == embeds.shape[0] * 32)   # u0 == 32*s0
    return embeds.sum()

torch.compile(f, dynamic=True, fullgraph=True)(torch.randn(2, 4, 8), torch.full((2, 4), 7))
```

Eager is fine. The pattern is what transformers' VLMs do in `get_placeholder_mask`:
`torch_compilable_check(inputs_embeds[special_mask].numel() == features.numel())`.

### Cause

`ShapeEnv._set_replacement(u0, 32*s23)` (`torch/fx/experimental/symbolic_shapes.py`, ~line 8184). `u0`'s range is
`[64, 9223372036854775806]` (`sys.maxsize - 1`); `32*s23` is `[64, int_oo]`, not a subset, so it inverts the
equation to tighten `s23`: `s23 = u0/32`, `bound_sympy(u0/32)` → `FloorToInt(upper)`. The division is done in
floating point: `9223372036854775806 / 32` is `2.8823037615171174e17`, which is exactly `2**58` as a double
(the true value is `2**58 - 0.0625`). So `s23` gets upper bound `2**58` instead of `2**58 - 1`, `32*s23` gets
`2**63`, and the re-check `tgt_bound.issubset(src_bound)` raises. Traced:

```
_update_var_to_range s23  req VR[2, 288230376151711744]  before VR[2, int_oo]   # 288230376151711744 == 2**58
```

### Possible fix

- Compute the inverted bound exactly: for `a == c * b` with integer `c`, use `FloorDiv(upper, c)` /
  `CeilDiv(lower, c)` (integers) instead of the rational bound through float `truediv`, or
- treat bounds at or above `sys.maxsize - 1` as `int_oo` before the final `issubset` assertion (they are the
  "unbounded" sentinel for size-like unbacked symbols, not a real limit), or
- downgrade the assertion: the range refinement is an optimization; failing to refine should skip the
  replacement, not raise.
