# dynamic=True: AOTAutograd synthetic base fails with `Expected !size_bytes_is_heap_allocated_ to be true`

### System info

- torch: `2.16.0a0+git57f02f8` (source build)
- transformers: `5.24.0.dev0` (main, git `046bdb8cc2`)
- Python 3.15, Linux. Reproduces on CPU and CUDA (H100)

### Description

With `dynamic=True`, a graph whose inputs share one storage, have no `._base`, may overlap, and include a
mutated one fails while compiling. `backend="aot_eager"` is enough to hit it, and static shapes work:

```python
import torch

def f(a, b):
    a.add_(1)
    return b.sum()

buf = torch.zeros(16, dtype=torch.int32)
a, b = buf[:8].detach(), buf[3:11].detach()        # overlapping views, no ._base
torch.compile(f, backend="aot_eager")(a, b)                 # ok
torch._dynamo.reset()
torch.compile(f, backend="aot_eager", dynamic=True)(a, b)   # fails
```

```
BackendCompilerFailed: backend='aot_eager' raised:
RuntimeError: Expected !size_bytes_is_heap_allocated_ to be true, but got false.
  torch/_functorch/_aot_autograd/runtime_wrappers.py: merge_view_inputs
  (fake_tensor: failed while attempting to run meta for aten.set_.source_Storage)
```

Full script: [`issues/repros/aot_synthetic_base_symbolic_nbytes.py`](repros/aot_synthetic_base_symbolic_nbytes.py).

`merge_view_inputs` builds a synthetic base for aliased inputs without `._base` with
`torch.empty((0,)).set_(example_alias.untyped_storage())`. `aten::set_(Tensor, Storage)` computes the new size
from `source.nbytes()`, which raises when the fake storage's size is a SymInt (here `4*s0 + 4*s1`).
Inputs that are provably disjoint skip this path (`compute_overlapping_inputs`). Inputs with symbolic offsets
usually can't be proven disjoint, so they reach it.

**Where it shows up.** gpt-oss-20b with its real MXFP4 experts (`kernels-community/gpt-oss-triton-kernels`),
`dynamic=True`, eval and train on CUDA. After a graph break in the expert kernels, the next graph receives
int32 routing buffers carved out of one allocation as inputs: one group of two 2-D views and one group of three
1-D views, all without `._base`, with symbolic sizes and offsets, and mutated. The static compile of the same
model fails earlier on `inductor-user-triton-constexpr-global`.

### Possible fix

Use the symbolic size in `set_(Storage)` (`source.sym_nbytes() / itemsize` and the SymInt `set_` overload), or
build the synthetic base in `merge_view_inputs` with
`set_(storage, 0, (storage.sym_nbytes() // itemsize,), (1,))`.
