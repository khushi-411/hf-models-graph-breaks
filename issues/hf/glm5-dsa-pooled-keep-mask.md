# GLM-5.3 DSA indexer: `pool_keys[:, keep]` boolean indexing graph-breaks in every indexed-attention layer

### System info

- torch: `2.16.0a0+git57f02f8` (source build, CUDA 12.8)
- transformers: `5.24.0.dev0` (main, git `046bdb8cc2`)
- Python 3.15, Linux; CUDA results on H100 (sm_90)

### Description

`Glm5NextIndexer.get_pooled_states` (`modeling_glm5_next.py:1009`):

```python
# Avoids static cache allocated positions
keep = pool_valid.any(0)
return pool_keys[:, keep], pool_indices[:, keep], pool_valid[:, keep]
```

The boolean mask gives a data-dependent shape (`Dynamic shape operator`, `aten.nonzero`). It is followed by
"Failed to handle graph break gracefully" at the same line, so the rest of that frame runs eagerly. This is in
the **language model's** sparse-attention indexer, not the vision tower, so it applies to text-only use too.

zai-org/GLM-5.3-Flash, 2 text layers (KDA + indexed attention): 32 graphs / 31 breaks overall (the vision
side adds the usual Qwen-VL-style breaks).

### Possible fix

Keep the pooled tensors at full size and carry `pool_valid` as a mask into the top-k selection: mask invalid
pools to `-inf` in the scores instead of dropping them.
