# `torch.compile`: SAM3 graph-breaks in every DETR decoder layer: `spatial_shapes` is a tensor, so `_get_coords` does `torch.arange(0, <tensor>)`

### System info

- transformers: `5.24.0.dev0` (main, git `b7fe69cb19`)
- torch: `2.16.0a0+git57f02f8` (source build)
- Python 3.15, Linux; checked on CPU and on CUDA (B200)

### Description

The DETR encoder collects its feature-map sizes as Python ints and then turns them into a tensor
(`modeling_sam3.py:1446-1463`):

```python
for features, pos_embed in zip(vision_features, vision_pos_embeds):
    height, width = features.shape[-2:]
    spatial_shapes.append((height, width))
...
spatial_shapes = torch.tensor(spatial_shapes, dtype=torch.long, device=features_flattened.device)
```

Each decoder layer computes the box relative-position bias from it (`:1825`):

```python
if spatial_shapes is not None and spatial_shapes.shape[0] == 1:
    spatial_shape = (spatial_shapes[0, 0], spatial_shapes[0, 1])        # 0-d tensors
    rpb_matrix = self._get_rpb_matrix(reference_boxes, spatial_shape)
```

and `_get_rpb_matrix` -> `_get_coords` (`:1715`, wrapped in `compile_compatible_method_lru_cache`) does

```python
coords_h = torch.arange(0, height, device=device, dtype=dtype) / height
coords_w = torch.arange(0, width, device=device, dtype=dtype) / width
```

`torch.arange` with a tensor bound needs its value (`aten._local_scalar_dense`), so Dynamo graph-breaks
("Data dependent operator") and, because it's inside the decoder-layer loop, then skips the frame
("graph break in loop"). It happens on every forward, in every decoder layer.

Harness (Sam3Config defaults, 2 vision / 2 text layers, 1 encoder and 1 decoder layer, image + text prompt):

| | eval_forward |
|---|---|
| static, CPU | 10 graphs / 9 breaks |
| static, CUDA | 13 graphs / 12 breaks (also `:1720`) |
| `dynamic=True` + Inductor, CUDA | 16 graphs, 1 recompile |

### Reproduction

`issues/hf/repros/sam3_spatial_shape_tensor_arange.py` (real `Sam3Model`, small config):

```
decoder layers=1: graphs=10 breaks=9  sites=['models/sam3/modeling_sam3.py:1719']
decoder layers=3: graphs=14 breaks=13 sites=['models/sam3/modeling_sam3.py:1719']
```

+2 breaks per decoder layer.

### Possible fix

Keep the sizes as Python ints next to the tensor and pass them down, as the Deformable-DETR-style models
do (`spatial_shapes_list`):

```python
spatial_shapes_list = [(h, w) for h, w in ...]            # ints from features.shape
...
spatial_shape = spatial_shapes_list[0]                    # in the decoder
```

(`_get_coords` only needs the sizes, and its `lru_cache` then also works in eager mode, since ints hash by
value while tensors hash by identity.)

### Affected

sam3 (eval). Likely also the other SAM3 variants that reuse this DETR decoder (sam3_video, sam3_lite_text);
not checked.
