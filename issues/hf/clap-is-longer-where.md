# CLAP: `torch.where(is_longer == 1)[0]` in the audio encoder graph-breaks

### System info

- torch: `2.16.0a0+git57f02f8` (source build, CUDA 12.8)
- transformers: `5.24.0.dev0` (main, git `046bdb8cc2`)
- Python 3.15, Linux; CUDA results on H100 (sm_90)

### Description

`ClapAudioEncoder.forward` (`modeling_clap.py:819`) selects the clips that get feature fusion:

```python
is_longer_list_idx = torch.where(is_longer_list == 1)[0]
...
if len(is_longer_idx) > 0:                       # ClapAudioPatchEmbed
    local_hidden_states = hidden_states[is_longer_idx, 1:, :, :]
    ...
    global_hidden_states[is_longer_idx] = self.fusion_model(global_hidden_states[is_longer_idx], local_hidden_states)
```

`torch.where(cond)` (nonzero) has a data-dependent shape. laion/clap-htsat-fused (the fused checkpoint, top-100
on the Hub): 3 graphs / 2 breaks in eval and train. Under `dynamic=True` it also recompiles (1 in eval, 2 in
train) as the number of longer clips changes.

### Possible fix

Run the fusion branch on the whole batch and blend with `torch.where(is_longer[:, None, None, None], fused,
global)`. This costs some compute for short clips but needs no data-dependent indexing.
