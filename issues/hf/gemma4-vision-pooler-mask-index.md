# Gemma 4 vision: `hidden_states[pooler_mask]` strips padding with boolean indexing

### System info

- torch: `2.16.0a0+git57f02f8` (source build, CUDA 12.8)
- transformers: `5.24.0.dev0` (main, git `046bdb8cc2`)
- Python 3.15, Linux; CUDA results on H100 (sm_90)

### Description

`Gemma4VisionModel.forward` (`modeling_gemma4.py:2105`):

```python
hidden_states, pooler_mask = self.pooler(...)
# Strip padding tokens. pooler_mask is True = valid, False = padding.
hidden_states = hidden_states[pooler_mask]
```

The boolean index has a data-dependent shape (`Dynamic shape operator`). gemma4 / gemma4_moe / gemma4_e4b:
8 graphs / 7 breaks each, from three sites:

- this one;
- `split_sizes(...).tolist()` in `get_image_features` (same as `vlm-split-image-features-tolist`);
- `inputs_embeds[image_mask].numel()` in the placeholder check (same as `placeholder-mask-bool-index-numel`).

### Possible fix

Without padding (the common single-resolution case) the mask is all True, and the features could be passed on
as a flat `(num_images * tokens, hidden)` view. With padding, use a `masked_scatter` into the placeholder
positions (as the LM side already does) instead of compacting first.

Related, separate bug: under `dynamic=True` on CUDA the pooler's `k = int((seq // length) ** 0.5)` is
miscomputed (`issues/inductor-cuda-int-sqrt-pow.md`). An integer square root
(`math.isqrt`) here would also avoid that.
