# `torch.compile` of fine-grained FP8 models crashes when DeepGEMM can't load (the Triton fallback only works in eager)

### System info

- torch: `2.16.0a0+git57f02f8` (source build, CUDA 12.8)
- transformers: `5.24.0.dev0` (main, git `046bdb8cc2`)
- Python 3.15, Linux; CUDA results on H100 (sm_90)
- accelerate, kernels 0.18.2

### Description

`fp8_linear` (`integrations/finegrained_fp8.py`) tries DeepGEMM first and falls back to the Triton kernel on
`ImportError`:

```python
if deepgemm_preferred:
    try:
        return deepgemm_fp8_fp4_linear(...)        # -> load_deepgemm_kernel() -> _load_deepgemm_kernel()
    except (ImportError, NotImplementedError, ValueError) as e:
        logger.warning_once("DeepGEMM declined this call, falling back to Triton. ...")
return finegrained_fp8_linear(...)
```

`_load_deepgemm_kernel` is `@torch._dynamo.allow_in_graph`, so under `torch.compile` it becomes an fx node
that runs during fake-tensor propagation. Its `ImportError` comes back as
`TorchRuntimeError: RuntimeError when making fake tensor call`, the `except` doesn't catch it, and compilation
fails.

`is_deepgemm_loadable()` only checks the environment (`kernels` installed, SM90/SM100, nvcc). It returns
`True` here, but the hub has no deep-gemm build for this torch, so `lazy_load_kernel("deep-gemm")` returns
`None`.

Eager: works (logs the fallback warning). Compiled: crashes. This was seen with Qwen/Qwen3.8-27B-FP8 and
deepseek-ai/DeepSeek-V3.2 (FP8, on-the-fly quantized small configs), on H100, in every scenario
(`check`, `dynamic`, `accuracy`).

### Reproduction

`issues/hf/repros/fp8_deepgemm_fallback_compile.py`: the same call chain without transformers, runs on CPU.

```
eager   : ok
compiled: TorchRuntimeError RuntimeError when making fake tensor call
```

### Possible fix

Resolve DeepGEMM availability outside the compiled region (try the load once in
`is_deepgemm_loadable` / at quantizer setup, cache the result, and gate `deepgemm_preferred` on it), so the
traced code never reaches a loader that can raise. Workaround: `TRANSFORMERS_DISABLE_DEEPGEMM_LINEAR=1`.
