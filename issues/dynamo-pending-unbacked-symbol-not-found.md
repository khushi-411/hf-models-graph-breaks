# Dynamo `PendingUnbackedSymbolNotFound` with `capture_scalar_outputs` when sizes kept in tensors are used as ints

### System info

- torch: `2.16.0a0+git57f02f8` (source build, CUDA 12.8)
- transformers: `5.24.0.dev0` (main, git `046bdb8cc2`)
- Python 3.15, Linux. CUDA (B300)

### Description

With `capture_scalar_outputs` and `capture_dynamic_output_shape_ops` on (`dynamic=True`), two models fail while
Dynamo wraps an op's output (`construct_tensor_variable` → `set_example_value` → `compute_unbacked_bindings`):

```
InternalTorchDynamoError: PendingUnbackedSymbolNotFound: Pending unbacked symbols {u4} not in returned outputs
FakeTensor(..., size=(1, 1, s70, s70), dtype=torch.int64)
Did you accidentally call new_dynamic_size() or item() more times than you needed to in your fake implementation?
```

Both models keep a size in a tensor and then use it as a Python int, which creates the unbacked symbol:

- **DeBERTa**, `disentangled_att_bias`: `att_span = torch.tensor(min(...))`, which is used in a slice of
  `rel_embeddings` and in `torch.clamp(relative_pos + att_span, 0, att_span * 2 - 1)`. The error is on the clamp
  output: `u4` comes from `att_span`, but the output shape doesn't contain it.
- **EnCodec**, `_pad1d`, after a graph break: the padding comes from int64 buffers (`_get_extra_padding_for_conv1d`)
  and goes to `F.pad`, which raises `{u0, u1} not in returned outputs` on an output of size `(s47, 1, s33 + u0 + u1)`.

This is an internal Dynamo error, and the default (backed) `dynamic=True` runs of both models pass.

**Not reduced yet.** Model-level commands:

```
python -m graph_breaks.dynamic --unbacked --device cuda --model deberta --scenario eval_forward
python -m graph_breaks.dynamic --unbacked --device cuda --model encodec --scenario eval_forward
```

### Possible fix

Symbols created while computing an op's arguments (the `.item()` behind `att_span`, the padding) should be bound
before the op whose output is checked, or the check should only look for symbols the op itself created. On
the transformers side, keeping these sizes as Python ints avoids the unbacked symbols entirely.
