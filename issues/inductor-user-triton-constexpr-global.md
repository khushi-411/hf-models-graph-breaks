# Inductor: user Triton kernel built at runtime loses its `constexpr_function` helpers (`NameError`)

### System info

- torch: `2.16.0a0+git57f02f8` (source build, CUDA 12.8)
- transformers: `5.24.0.dev0` (main, git `046bdb8cc2`)
- Python 3.15, Linux; CUDA results on H100 (sm_90)
- triton 3.9.0, kernels 0.18.2

### Description

A user-defined Triton kernel whose source is defined at runtime (`exec` into a globals dict, `__module__` set
to a synthetic module) launches fine in eager. Under `torch.compile`, Inductor compiles the kernel again and
the `constexpr_function` helpers it calls are missing:

```
InductorError: SubprocException ... Name=_finalize_matmul
  USE_FUSED_MIXED_PREC_ACC: tl.constexpr = (cuda_capability_geq(10, 0) ...
NameError('cuda_capability_geq is not defined')
```

The helper is in the kernel function's `__globals__` but not in its `__module__`. A plain module-level kernel
with the same helper compiles fine.

This is how `kernels-community/gpt-oss-triton-kernels` builds its kernels (`specialize()` /
`define_kernel()`), and transformers' MXFP4 MoE path (gpt-oss) launches `_finalize_matmul` from there. So
`torch.compile` of any MXFP4 gpt-oss model fails. Eager works.

### Reproduction

`issues/repros/inductor_user_triton_constexpr_global.py` (about 60 lines, needs CUDA):

```
eager   : True
compiled: InductorError NameError('use_double is not defined')
```

Model level: `python -m graph_breaks.accuracy --model gpt_oss_mxfp4 --device cuda` (real
openai/gpt-oss-20b MXFP4 checkpoint, first 2 layers).

### Possible fix

When Inductor re-emits a user kernel, resolve its global names through `kernel.fn.__globals__` (or the
JITFunction's capture scope) rather than `kernel.fn.__module__`.
